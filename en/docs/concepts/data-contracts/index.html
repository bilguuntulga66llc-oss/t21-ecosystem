Data contracts

Every T21 response has a versioned envelope and a domain schema. Contracts change under a compatibility policy.

REST response envelope

FieldMeaning
api_schema_versionThe API contract version (api.v2.0.0)
sdk_schema_versionThe SDK contract version (sdk.v2.0.0)
output_schema_versionThe output schema version (1.7.0)
generated_atWhen the response was generated
request_idThe request's identifier. Quote it when reporting a problem.
source, endpoint, paramsThe response's origin, endpoint and parameters
dataThe domain payload

Each domain payload has its own schema, for example valuation_history.v1 and listed_identity.v1. MCP results and Developer Platform token responses have other shapes.

Versions

REST endpoints are under /v1/. The T21 API is at version 2.1.0 and the Developer Platform at 0.2.0.

Compatibility policy

  • A field may be added to a contract in force without changing its existing values or structure.
  • A breaking change raises the major version and publishes a migration period, the replacing contract, migration instructions and a changelog.
  • A deprecated endpoint states its deprecation date in the Deprecation header (RFC 9745), its replacement in a Link header with rel="successor-version", and the version that removes it in X-MSE-Removal-Target. The Link header points to this policy with rel="deprecation".
