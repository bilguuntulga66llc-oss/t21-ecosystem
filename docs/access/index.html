    Баримт бичиг / Access

    Access

    T21 API-д Developer Platform-ийн олгосон token-оор хандана. Token-ий scope нь хандах endpoint-ийг тодорхойлно.

    Authentication

    Credential secret-ийг POST /v1/token-д илгээж token авна. scopes жагсаалт өгвөл token-ий scope-ийг нарийсгана. Token 300 секунд хүчинтэй.

    Нэвтэрсэн бүртгэл бүр open:read-тэй. Бусад scope-ийг T21 зөвшөөрнө. Credential үүсгэх, token авах бүрд Developer Platform үүнийг шалгана. T21-ийн зөвшөөрөөгүй scope-той credential үүсгэвэл HTTP 403, scope_not_grantable алдаа буцаана. Зөвшөөрлийг цуцалбал тухайн scope-той credential цуцлагдана.

    T21 API-д token-ийг Authorization: Bearer <access_token> эсвэл x-api-key header-ээр илгээнэ. Хоёуланг нь илгээвэл x-api-key-г ашиглана.

    Token нь t21_access.v1 contract бүхий PASETO v4.public (Ed25519). Claim: iss, aud, sub, project_ref, credential_ref, jti, iat, nbf, exp, scopes.

    Хоёр түвшин

    open:read-тэй token нь нээлттэй түвшинд дараах хүрээнд хандана. Бусад scope нь бүрэн түвшин: бүх түүхтэй.

    90 хоног нь өгөгдөлд хадгалагдсан хамгийн сүүлийн арилжааны өдрөөр төгсөнө.

    Platform-ийн token-оор авсан хариу бүр access талбартай. Бүрэн түвшинд {"tier": "full"}, нээлттэй түвшинд rule нь хэрэглэсэн дүрмийг заана. 90 хоногийн дүрэмд from, to нь хугацааны хоёр захыг, outside_window нь хугацаанаас гадуурх тул оруулаагүй мөрийн тоог заана. Мөрийг бүтнээр нь өгнө, эсвэл оруулахгүй. Утгыг өөрчлөхгүй.

    90 хоногоос өмнөх огноо асуувал HTTP 403, outside_open_access алдаа буцаана. Алдаа нь тухайн параметр болон хугацааг нэрлэнэ. Хамгийн сүүлийн тайлан, одоогийн төлөвөөс өмнөх төлөвийг асуух параметрт мөн ийм алдаа буцаана.

    Credential шаардахгүй endpoint

    GET /v1/system/health, GET /v1/system/consumption-manifest, GET /v1/system/source-registry, GET /v1/system/datasets.

    Үндэсний статистикийн хорооны хүснэгтүүд (GET /v1/macro/statistics, GET /v1/macro/statistics/{table_id}) credential шаардахгүй. Хариу нь access: {"tier": "public"} гэж заана. Rate limit нь хаяг тус бүрээр үйлчилнэ.

    Rate limit

    Developer Platform-ийн token-оор илгээсэн хүсэлтэд project тус бүрээр rate limit үйлчилнэ. open:read-ийн хязгаар бага бөгөөд бүртгэл тус бүрээр, түүний бүх project-ийг нийлүүлж тоологдоно. Rate limit хэтэрвэл 429 буцаана. Хүсэлтийн давтамжийг Retry-After болон X-RateLimit-Limit, X-RateLimit-Remaining, X-RateLimit-Reset header-ийн дагуу тохируулна. X-RateLimit-Reset нь хязгаар шинэчлэгдэх хүртэлх секунд.

    Developer Platform алдааг {"error": {"code": "…"}}, харин T21 API token-ий баталгаажуулалтын алдааг {"detail": {"code": "…"}} хэлбэрээр буцаана. Accept: application/problem+json header илгээвэл хоёр үйлчилгээ алдааг RFC 9457 Problem Details хэлбэрээр буцаана: type, title, status, detail, instance, code. T21 API-ийн хариуны request_id-г асуудал мэдэгдэхэд ашиглана.
